## 4. Генерация кода

На основе MD + HOMEWORK_REQUIREMENTS.md реализуй:

### Структура и FSD-консистентность

```
src/features/formExamples/          — папка задания (аналог features/taskList из LESSON-3)
  ├── api/                          — API-модуль (если нужен)
  ├── model/                        — типы, store
  └── ui/                           — компоненты (формы, поля, кнопки)
```

**FSD-консистентность:**
- ✅ `src/features/formExamples/` — правильно, по аналогии с `src/features/taskList/` из LESSON-3
- ✅ Общие компоненты формы (input-обёртки, кнопки) — `src/shared/ui/form/` (если понадобятся)
- ❌ Не трогай `src/entities/tasks/` и другие папки из LESSON-3
- ❌ Не меняй существующий код — делай только новую фичу

**Правила TypeScript:**
- Строгая типизация (`strict: true` в tsconfig уже включён)
- Экспортируй типы форм через `z.infer<typeof schema>`
- Файлы — `.ts` / `.tsx`, никаких `.js`

**Стилизация:**
- CSS Modules (`.module.css`) или обычные CSS-файлы — по аналогии с LESSON-3

### Что реализовать (по 4. практическое задание.md)

1. **Форма регистрации** (4 балла)
   - Поля: `username`, `email`, `password`, `confirmPassword`
   - React Hook Form (не Formik)
   - Валидация: все поля обязательны, `email @`, пароль ≥ 6, подтверждение совпадает
   - Ошибки рядом с полями

2. **Zod схема** (2 балла)
   - `zodResolver` из `@hookform/resolvers`
   - Декларативная схема вместо ручной логики

3. **Динамические социальные ссылки** (4 балла)
   - `useFieldArray` для массива полей
   - Кнопки "Добавить ссылку" / "Удалить"
   - Каждая ссылка валидируется как URL (`z.string().url()`)

### Не реализовывать
- ❌ Wizard-формы (`useActionState` из React 19) — бонус, нет времени
- ❌ Formik — React Hook Form достаточно

### Правила из HOMEWORK_REQUIREMENTS.md
- Ветка: `lesson-4`
- Чеклист в `LESSON-4.md`
- `package-lock.json` — есть
- `"engines": { "node": ">=20" }` — в `package.json`
- Скрипты: `dev`, `build`, `lint`
- Не коммитить: `node_modules/`, `dist/`, `.env`

### Правила из фидбека (prReport.md)
- Использовать `setTasks((prev) => prev.filter(...))` — `prev`-паттерн в сеттерах
- Чеклист с `[x]` и `[ ]`
