# Итоговый проект


**Цель**

Доработать исходный проект ([REACT_PRO_final_project_base](https://github.com/NelliEfr/REACT_PRO_final_project_base)), применив знания из курса: оптимизировать, структурировать и добавить современные фичи, опираясь на изученный материал.


## Что уже реализовано (по проекту)


- **Redux Toolkit + RTK Query** подключены.
- **React Router v6** используется. Есть защищённые страницы.
- **React Hook Form** и **yup** реализованы на страницах регистрации и авторизации.
- Реализованы поиск со *query-параметрами + debounce*, *инфинит-скролл*, *корзина*, *контекст пользователя*.
- **Webpack** сборка настроена (папка webpack/) и есть конфиги ESLint/Prettier/Stylelint и TS (в корне).

Пока нет **React.Portal**, **useRef-кейсов**, **оптимизаций рендеринга**, **сборки esbuild/swc**, **React 19 hooks** и полной архитектурной реорганизации.


## Задачи


### **1. Архитектура и структураЧто сделать:
- Вынести UI-компоненты (например, Button, Input, Loader) в src/shared/ui.
- Разделить фичи по папкам — например, src/features/cart/, src/features/auth/, src/features/search/.
- Убрать лишние проп-пробросы, где можно использовать селекторы из RTK Query или Redux.
- Проанализировать проект и найти часто встречающиеся UI-компоненты (Button, Input, Loader). Вынесите эти компоненты в src/shared/ui и использовать их в дальнейшем при разработке

**Где: **src/ → организовать слои: shared/, features/, pages/.

**Чек-лист:
- В shared/ui лежат только презентационные (UI) компоненты:
- без бизнес-логики,
- без работы с API,
- без доступа к стору,
- принимают данные и коллбэки только через props..
- Фичи изолированы в отдельных папках.
- Нет глубоких prop-chain’ов без необходимости.

### **2. Оптимизация рендеровЧто сделать:
- Найти дубли рендеров через React DevTools Profiler.
- Обернуть компоненты, получающие неизменные props, в React.memo.
- В списках (например, товаров или корзины) применить useMemo/useCallback там, где есть вычисления или колбэки.

**Где: **Компоненты массива — src/features/products/..., src/features/cart/....

**Чек-лист:
- Использован Profiler — найден hotspot.
- React.memo применяется там, где эффективно.
- useMemo/useCallback оптимизируют сложные вычисления/функции.

### **3. React.Portal для модалокЧто сделать:
- В public/index.html добавить .
- Реализовать компонент Modal в src/shared/ui/Modal через ReactDOM.createPortal.

**Чек-лист:
- Модальное окно работает через портал.
- Закрытие модального окна через клик по иконке крестика, клику вне области модалки и нажатие на клавишу ESC корректно обрабатываются
- Фокус обрабатывается корректно:
- при открытии модального окна начальный фокус устанавливается на кнопку закрытия модалки (иконку крестика),
- при закрытии модального окна — фокус возвращается на элемент-триггер.

### **4. useRef — реальное применениеЧто сделать:
- Использовать useRef для хранения состояния между рендерами без перерендера — например, счётчик кликов или таймер.
- Автофокус на инпут формы (регистрации/логина) при монтировании через ref.

**Где: **src/features/auth/LoginForm.jsx, или в shared/ui/Modal.

**Чек-лист:
- Пример useRef без рендера.
- Автофокус или другое взаимодействие с DOM.

### **5. Собственные сборки (esbuild/swc)Что сделать:
- Создать альтернативный сборочный конфиг: например, esbuild.config.js или vite.config.js с SWC.
- Сравнить build time и output-size с Webpack, записать результаты.

**Чек-лист:
- Сборка через esbuild или SWC работает.
- В README приведено сравнение (размер, время).

### **6. Применение React 19 HooksЧто сделать:
- В одной форме (например, комментарий) использовать useActionState для отправки и автоматического reset.
- Или useOptimistic для мгновенных UI-реакций (например, добавление товара в избранное).

**Где: **например, src/features/productDetails/AddCommentForm.jsx или CartItem.
- Можно использовать любой хук из тех, что появились в 19 реакте, однако необходимо обосновать его применение на защите

**Чек-лист:
- Использован useActionState или useOptimistic.
- UI реагирует до ответа сервера (оптимистично).
