Цель

Научиться использовать хук useRef в React для хранения значений между рендерами и доступа к DOM-элементам. Разобраться, как с помощью ref.current избежать лишних перерисовок компонента и безопасно управлять HTML-элементами напрямую.

Почему важно

В React принято не взаимодействовать напрямую с DOM — это нарушает декларативный подход. Однако бывают ситуации, когда без прямого доступа не обойтись: фокус на инпут, измерение ширины элемента, сохранение предыдущего значения и так далее.

В этих случаях хук useRef — мощный инструмент. Он позволяет:

  • сохранить данные между рендерами без триггера обновления;

  • получить ссылку на DOM-элемент и работать с ним напрямую;

  • заменить локальное состояние, если оно не влияет на отрисовку.

Где используют useRef

1. Сохранение значения между рендерами

В React любое обновление состояния с помощью useState вызывает повторный рендер компонента. Но бывают ситуации, когда нужно сохранить информацию между рендерами, не вызывая при этом повторную отрисовку.

Например:

  • Мы хотим отслеживать количество кликов, но не отображать это число в интерфейсе.

  • Или сохранить время предыдущего действия без влияния на отображение.

  • Или просто временно кешировать значение.

Пример из UX

На сайте доставки вы кликаете по кнопке «Отследить заказ», каждый клик сохраняется в clickCount. Пользователь не видит счетчик, но разработчики могут использовать его:

  • для A/B-тестов (какой UI вызывает больше кликов);

  • или чтобы после трех попыток показать уведомление: «Номер отслеживания скоро появится. Пожалуйста, подождите».

В таких случаях useRef — лучший выбор.

import { useRef } from 'react';

function ClickTracker() {

 const clickCount = useRef(0);

 const handleClick = () => {

   clickCount.current += 1;

   console.log('Кликов:', clickCount.current);

 };

 return <button onClick={handleClick}>Кликни меня</button>;

}

Пояснение:

  • clickCount — объект, который React не обновляет при изменении .current.

  • clickCount.current — просто поле, в которое можно записывать любые значения.

  • Компонент не перерисуется, даже если вы 100 раз обновите clickCount.current.

Когда использовать?

  • Ведение логов и статистики.

  • Отслеживание таймингов или флагов (например, «первый ли это клик»).

  • Оптимизация ререндеров (например, при работе с canvas или WebGL).

  • Вспомогательные счетчики, которые не влияют на UI напрямую.

2. Предыдущее значение пропса или состояния

Иногда нужно узнать, что было раньше, чтобы сравнить это с текущим значением. Например:

  • отследить, изменилось ли значение;

  • выполнить анимацию только при изменении;

  • сравнить предыдущее и текущее значения и сделать вывод.

Пример из UX

В интернет-магазине при оформлении заказа отображается блок «Ваша скидка изменилась», только если промокод стал выгоднее. useRef помогает сравнить старое и новое значения скидки — пользователь видит уведомление только при реальном изменении, а не на каждом рендере.

Для этого удобно использовать useRef — он сохраняет значение между рендерами без его автоматического обновления.

import { useEffect, useRef } from 'react';

function PreviousValueExample({ count }) {

 const prevCount = useRef(count);

 useEffect(() => {

   console.log(`Предыдущее значение: ${prevCount.current}`);

   prevCount.current = count;

 }, [count]);

 return <div>Текущее: {count}</div>;

}

Что происходит?

  1. prevCount изначально равен count (текущему значению на первом рендере).

  2. При каждом изменении count срабатывает useEffect.

  3. Внутри useEffect мы:

    • логируем предыдущее значение;

    • обновляем ref.current, чтобы оно стало новым предыдущим для следующего рендера.

Зачем нужно?

Часто используют для:

  • сравнения текущего и предыдущего значений;

  • построения графиков и анимаций;

  • условного поведения (например, если значение увеличилось — запустить таймер);

  • избежания ненужных side-effect'ов, если значение не изменилось.

3. Работа с DOM напрямую

Иногда в React-приложении нужно напрямую взаимодействовать с DOM-элементом — например, установить фокус на поле ввода, прокрутить к нужному блоку или измерить его. В таких случаях удобно использовать хук useRef для получения ссылки на DOM-элемент.

Пример из UX

После клика на кнопку «Поделиться корзиной» появляется модалка с полем ввода email. inputRef.current.focus() ставит курсор в поле автоматически — пользователь сразу начинает ввод, не кликая вручную.

Для примера установим фокус на input при загрузке:

import { useRef, useEffect } from 'react';

function InputFocus() {

 const inputRef = useRef(null);

 useEffect(() => {

   inputRef.current.focus();

 }, []);

 return <input ref={inputRef} placeholder="Фокус при загрузке" />;

}

В этом коде:

  1. useRef(null) создает объект-ссылку с полем current.

  2. В ref={inputRef} прикрепляем эту ссылку к DOM-элементу <input>.

  3. В useEffect вызываем метод focus() у DOM-элемента, доступного по inputRef.current.

useEffect с пустым массивом зависимостей ([]) гарантирует, что код выполнится только после первого рендера — когда DOM уже создан и ref прикреплен.

Что еще можно делать через ref.current?

Ссылка на DOM-элемент дает доступ ко всем стандартным методам и свойствам HTML-элемента:

  • focus() — установить фокус на элемент;

  • scrollIntoView() — прокрутить страницу к элементу;

  • getBoundingClientRect() — получить координаты и размеры элемента;

  • classList.add/remove — управлять CSS-классами напрямую (хотя в React это делают через className);

  • value, checked и другие свойства для форм.

Полезно, если:

  • работаем с фокусом (например, для улучшения доступности);

  • выполняем анимацию или измерение размеров;

  • нужно интегрироваться с внешними библиотеками, которые требуют прямого доступа к DOM.

4. Управление таймерами: debounce и throttle

Еще одно важное и очень практичное применение useRef — хранение идентификаторов таймеров, например, для реализации debounce или throttle.

Это нужно, чтобы:

  • избежать частых вызовов API при вводе (например, в строке поиска);

  • снизить нагрузку на приложение;

  • реализовать отложенное или ограниченное по частоте выполнение функций.

Пример из UX

В форме поиска отеля пользователь вводит город. Благодаря debounce, запросы к серверу отправляются не на каждый символ, а только через 500 мс после паузы. Это ускоряет приложение и снижает нагрузку. Пользователь видит плавную загрузку и результаты без задержек.

import { useRef } from 'react';

function SearchInput() {

 const timeoutRef = useRef(null);

 const handleChange = (event) => {

   const value = event.target.value;

   clearTimeout(timeoutRef.current); // сбрасываем предыдущий таймер

   timeoutRef.current = setTimeout(() => {

     console.log('Выполняем поиск по:', value);

     // тут может быть API-запрос

   }, 500);

 };

 return <input onChange={handleChange} placeholder="Введите запрос" />;

}

Разбираем блок кода:

  • timeoutRef хранит ID текущего таймера.

  • При каждом onChange отменяем предыдущий setTimeout.

  • Новый таймер сохраняем в timeoutRef.current.

  • UI не ререндерится — все управление идет через ref.

Аналогично можно использовать для:

  • requestAnimationFrame — сохранить ID, чтобы потом отменить;

  • setInterval — прекратить повторяющееся выполнение;

  • throttle — запускать колбэк не чаще, чем раз в N миллисекунд.

Этот паттерн особенно полезен в интерактивных интерфейсах и в оптимизации производительности.

5. Хранение внешних ресурсов (например, WebSocket)

useRef подходит не только для хранения DOM-элементов, но и для объектов, которые не должны вызывать ререндер. Один из таких практических кейсов — хранение экземпляра WebSocket (или EventSource, Audio, MediaRecorder и так далее).

Зачем нужно?

  • Подключение к WebSocket не должно зависеть от UI.

  • Нам важно не пересоздавать соединение при каждом ререндере.

  • ref.current — стабильная ссылка на соединение на протяжении всей жизни компонента.

  • В useEffect можно создать сокет, подписаться на сообщения, а в cleanup — закрыть соединение.

Пример из UX

В приложении поддержки при переходе на вкладку «Чат с оператором» WebSocket уже открыт. Пользователь видит мгновенное подключение без анимаций «Подключение...». Соединение создано заранее и сохранено в ref.

Рассмотрим пример с подключением к WebSocket:

import { useEffect, useRef } from 'react';

function ChatConnection() {

 const socketRef = useRef(null);

 useEffect(() => {

   socketRef.current = new WebSocket('wss://example.com/chat');

   socketRef.current.onmessage = (event) => {

     const message = JSON.parse(event.data);

     console.log('Новое сообщение:', message);

     // Здесь можно обновить состояние

   };

   return () => {

     socketRef.current.close();

   };

 }, []);

 const sendMessage = (text) => {

   if (socketRef.current?.readyState === WebSocket.OPEN) {

     socketRef.current.send(JSON.stringify({ type: 'chat', text }));

   }

 };

 return (

   <div>

     <button onClick={() => sendMessage('Привет!')}>Отправить</button>

   </div>

 );

}

Ключевые моменты:

  • useRef(null) хранит WebSocket, который не перерендеривает компонент;

  • socketRef.current создается один раз и живет до размонтирования;

  • можно свободно вызывать .send, .close, .addEventListener, не опасаясь ререндеров;

  • на unmount мы корректно закрываем соединение.

Прием работает не только с WebSocket:

  • MediaStream, MediaRecorder, AudioContext — при хранении ресурсов мультимедиа.

  • AbortController — для отмены fetch-запросов.

  • EventSource — с SSE-потоками.

  • С любыми внешними классами или подключениями, где важно не терять ссылку и не создавать заново при каждом рендере.

Важно

useRef позволяет создавать долгоживущие и стабильные ссылки, которые React не трогает при обновлениях UI. Это делает его идеальным инструментом для управления состоянием вне React-мира, особенно в интеграциях и оптимизациях.

Распространенные ошибки

  1. Изменить .current и ждать, что произойдет ререндер, — этого не будет.

  2. Пытаться обращаться к ref.current до монтирования компонента — он будет null.

  3. Слишком активно использовать useRef вместо состояния, когда нужно реактивное обновление.
