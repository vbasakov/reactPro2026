Цель

Научиться управлять сложными формами, обеспечивать асинхронную валидацию, обрабатывать массивы в полях (field array), интегрировать формы с API. Изучить подходы, реализованные в популярных библиотеках Formik и React Hook Form, а также ознакомиться с новым подходом от React 19 (useActionState).

Почему важно управлять формами?

Формы используются повсеместно: от простых регистраций до сложных конфигураций и CRM-систем. При этом именно формы часто становятся источником багов: пропущенная валидация, некорректное поведение при отправке, ошибки при обновлении. Чем сложнее форма, тем выше риск. Чтобы создавать надежные интерфейсы, необходимо понимать, как устроены формы в React и как избежать дублирования и неконтролируемых состояний.

Ключевые подходы к управлению формами

Formik и React Hook Form — две популярные библиотеки для работы с формами.

Formik

Упрощает работу с локальным состоянием формы, удобно для вложенных структур. Предоставляет читаемый API и хорошую поддержку TypeScript.

Пример: простая форма входа с ручной валидацией.

import { Formik, Form, Field, ErrorMessage } from 'formik';

function LoginForm() {

 const validate = (values) => {

   const errors = {};

   if (!values.email) {

     errors.email = 'Обязательное поле';

   } else if (!values.email.includes('@')) {

     errors.email = 'Некорректный email';

   }

   if (!values.password) {

     errors.password = 'Обязательное поле';

   } else if (values.password.length < 6) {

     errors.password = 'Минимум 6 символов';

   }

   return errors;

 };

 return (

   <Formik

     initialValues={{ email: '', password: '' }}

     validate={validate}

     onSubmit={(values) => {

       console.log('Отправка формы:', values);

     }}

   >

     <Form>

       <label>Email</label>

       <Field name="email" type="email" />

       <ErrorMessage name="email" component="div" />

       <label>Пароль</label>

       <Field name="password" type="password" />

       <ErrorMessage name="password" component="div" />

       <button type="submit">Войти</button>

     </Form>

   </Formik>

 );

}

React Hook Form

Построен на хуках, эффективен за счет минимального количества ререндеров. Подходит для больших форм и динамических полей.

Пример: форма входа, но с использованием register и ручной валидации.

import { useForm } from 'react-hook-form';

function LoginFormRHF() {

 const {

   register,

   handleSubmit,

   formState: { errors },

 } = useForm();

 const onSubmit = (data) => {

   console.log('Отправка формы:', data);

 };

 return (

   <form onSubmit={handleSubmit(onSubmit)}>

     <label>Email</label>

     <input

       {...register('email', {

         required: 'Обязательное поле',

         validate: (value) =>

           value.includes('@') || 'Некорректный email',

       })}

     />

     <p>{errors.email?.message}</p>

     <label>Пароль</label>

     <input

       type="password"

       {...register('password', {

         required: 'Обязательное поле',

         minLength: {

           value: 6,

           message: 'Минимум 6 символов',

         },

       })}

     />

     <p>{errors.password?.message}</p>

     <button type="submit">Войти</button>

   </form>

 );

}

Что поддерживают обе библиотеки?

  • Декларативное описание формы — структура читается как схема данных.

  • Пошаговая и финальная валидация — ошибки показываются при фокусе или сабмите.

  • Интеграция с API — легко подключается логика отправки через Axios/fetch.

  • Централизованное отображение ошибок — можно обернуть логику в общие компоненты или хуки.

Обе библиотеки применяются в production-приложениях и покрывают большинство сценариев — от простых форм до сложных конфигураций и таблиц с динамическими полями.

Схемы валидации: yup и zod

Для строгой и повторно используемой валидации применяются схемы. Они описывают, какие значения допускаются в каждом поле, и позволяют централизованно управлять логикой ошибок.

  • yup — простой и понятный синтаксис, используется по умолчанию в Formik;

  • zod — тесно интегрируется с TypeScript, позволяет получать типы напрямую из схем.

Обе библиотеки позволяют:

  • централизованно описывать допустимые значения;

  • выносить логику валидации за пределы компонентов;

  • использовать те же правила валидации как на клиенте, так и на сервере;

  • и даже извлекать типы полей из схем (в случае с zod).

Пример: валидация с yup в Formik.

import { Formik, Form, Field, ErrorMessage } from 'formik';

import * as yup from 'yup';

// схема валидации

const schema = yup.object({

 name: yup.string().required('Введите имя'),

 email: yup.string().email('Неверный email').required('Email обязателен'),

});

export function ContactForm() {

 return (

   <Formik

     initialValues={{ name: '', email: '' }}

     validationSchema={schema}

     onSubmit={(values) => console.log(values)}

   >

     <Form>

       <label>Имя:</label>

       <Field name="name" />

       <ErrorMessage name="name" component="div" />

       <label>Email:</label>

       <Field name="email" />

       <ErrorMessage name="email" component="div" />

       <button type="submit">Отправить</button>

     </Form>

   </Formik>

 );

}

Что делает yup:

  • проверяет типы (string, email);

  • устанавливает обязательность поля (required);

  • возвращает ошибки, которые автоматически отображаются через <ErrorMessage />.

Пример: валидация с zod в React Hook Form.

import { useForm } from 'react-hook-form';

import { z } from 'zod';

import { zodResolver } from '@hookform/resolvers/zod';

// описание схемы

const schema = z.object({

 username: z.string().min(3, 'Минимум 3 символа'),

 age: z.number().min(18, 'Доступ с 18 лет'),

});

type FormData = z.infer<typeof schema>;

export function ProfileForm() {

 const {

   register,

   handleSubmit,

   formState: { errors },

 } = useForm<FormData>({

   resolver: zodResolver(schema),

 });

 const onSubmit = (data: FormData) => {

   console.log(data);

 };

 return (

   <form onSubmit={handleSubmit(onSubmit)}>

     <label>Имя пользователя:</label>

     <input {...register('username')} />

     {errors.username && <p>{errors.username.message}</p>}

     <label>Возраст:</label>

     <input type="number" {...register('age', { valueAsNumber: true })} />

     {errors.age && <p>{errors.age.message}</p>}

     <button type="submit">Сохранить</button>

   </form>

 );

}

Что делает zod:

  • поддерживает строгую типизацию (возвращает FormData);

  • интегрируется с React Hook Form через zodResolver;

  • упрощает использование форм в TypeScript, особенно в больших проектах.

Оба подхода позволяют использовать вложенные схемы, массивы (array(), z.array()) и асинхронную валидацию через .test() или .refine() — например, при проверке уникальности email на сервере.

Работа с Field Arrays и динамическими полями

В сложных интерфейсах часто требуется динамически добавлять или удалять группы полей:

  • список товаров в заказе;

  • множество участников в форме регистрации;

  • контактные данные с возможностью добавления новых блоков.

RHF предоставляет удобный хук useFieldArray, позволяющий управлять массивами данных без потери производительности и с сохранением всей валидации.

import { useForm, useFieldArray } from 'react-hook-form';

export function ParticipantsForm() {

 const { register, control, handleSubmit } = useForm({

   defaultValues: {

     participants: [{ name: '' }],

   },

 });

 const { fields, append, remove } = useFieldArray({

   control,

   name: 'participants',

 });

 const onSubmit = (data) => {

   console.log(data);

 };

 return (

   <form onSubmit={handleSubmit(onSubmit)}>

     <h3>Участники:</h3>

     {fields.map((field, index) => (

       <div key={field.id}>

         <input

           {...register(`participants.${index}.name`)}

           placeholder={`Участник #${index + 1}`}

         />

         <button type="button" onClick={() => remove(index)}>Удалить</button>

       </div>

     ))}

     <button type="button" onClick={() => append({ name: '' })}>

       Добавить участника

     </button>

     <button type="submit">Отправить</button>

   </form>

 );

}

Особенности:

  • useFieldArray отслеживает уникальные id, даже если пользователь удаляет или добавляет элементы;

  • валидация и значения сохраняются корректно;

  • минимум ререндеров.

Formik требует немного больше ручной настройки, но также справляется с подобными сценариями.

import { Formik, Field, Form, FieldArray } from 'formik';

export function ProductsForm() {

 return (

   <Formik

     initialValues={{ products: [{ title: '' }] }}

     onSubmit={(values) => console.log(values)}

   >

     {({ values }) => (

       <Form>

         <h3>Список товаров:</h3>

         <FieldArray name="products">

           {({ push, remove }) => (

             <>

               {values.products.map((_, index) => (

                 <div key={index}>

                   <Field name={`products.${index}.title`} placeholder="Название товара" />

                   <button type="button" onClick={() => remove(index)}>Удалить</button>

                 </div>

               ))}

               <button type="button" onClick={() => push({ title: '' })}>

                 Добавить товар

               </button>

             </>

           )}

         </FieldArray>

         <button type="submit">Сохранить</button>

       </Form>

     )}

   </Formik>

 );

}

Особенности:

  • FieldArray предоставляет методы push, remove и insert;

  • значения синхронизируются с initialValues;

  • можно подключать yup-схему для валидации каждого элемента массива.

Нативный подход React 19: useActionState

С выходом React 19 разработчики получили возможность управлять формами без сторонних библиотек, используя встроенные хуки и server actions. Это приближает форму к идее «чистого» React — без Redux, Formik, RHF и даже без необходимости вручную управлять локальным состоянием.

Основные инструменты:

  • useActionState — управляет состоянием формы и результатами действия;

  • useFormStatus — сообщает о текущем статусе выполнения действия (загрузка, успех, ошибка);

  • <form action={}> — форма отправляет данные напрямую на функцию-обработчик (server action).

'use client';

import { useActionState, useFormStatus } from 'react';

// Серверное действие (может быть размещено в отдельном файле)

async function saveFormData(prevState, formData) {

 const name = formData.get('name');

 if (!name) {

   return { error: 'Имя обязательно' };

 }

 await new Promise((res) => setTimeout(res, 1000)); // Симуляция задержки

 return { success: Привет, ${name}! };

}

function SubmitButton() {

 const { pending } = useFormStatus();

 return (

   <button type="submit" disabled={pending}>

     {pending ? 'Отправка...' : 'Отправить'}

   </button>

 );

}

export default function NativeForm() {

 const [state, formAction] = useActionState(saveFormData, {});

 return (

   <form action={formAction}>

     <input type="text" name="name" placeholder="Введите имя" />

     <SubmitButton />

     {state?.error && <p style={{ color: 'red' }}>{state.error}</p>}

     {state?.success && <p style={{ color: 'green' }}>{state.success}</p>}

   </form>

 );

}

Особенности:

  • Никаких useState — useActionState берет управление на себя.

  • Без reset и value — данные передаются через FormData, не нужно синхронно управлять полями.

  • Отлично работает с сервером — saveFormData может быть server action, обрабатывающим POST-запрос.

Применимость

Подходит для:

  • простых форм с минимальной логикой;

  • проектов, использующих App Router и server actions;

  • случаев, когда не требуются сложная валидация, вложенные поля или массивы.

Ограничения:

  • нет полной поддержки сложных структур (field arrays, вложенных объектов);

  • типизация слабее, чем у zod/yup или RHF;

  • требует React 19 и фичи server actions, поддерживаемых не во всех средах (только в App Router).

Этот подход отлично работает как стартовая точка для простых форм и как пример архитектурной минималистичности, когда важно сохранить как можно меньше зависимостей.

Почему важно понимать оба подхода?

Formik и RHF зарекомендовали себя в production-приложениях и покрывают большинство кейсов. Однако нативный подход React постепенно развивается и в будущем может заменить часть сторонних решений. Знание обеих стратегий помогает:

  • выбирать инструменты под задачу;

  • понимать trade между гибкостью и простотой;

  • интегрировать формы в архитектуру с учетом контекста (SPA vs SSR, масштаб, требования к UX).

Многошаговые формы (wizard)

Во многих интерфейсах форма разбивается на шаги:

  • анкеты;

  • опросники;

  • оформление заказа;

  • сложные регистрации.

Важно:

  • сохранять данные между шагами;

  • валидировать поля каждого шага отдельно;

  • предупреждать пользователя при попытке уйти со страницы с несохраненными изменениями (dirty).

Управление шагами и хранение данных

Есть два способа реализации:

Подход

Когда использовать?

Преимущества

useState + useEffect

При простых формах без глубокой валидации

Полностью контролируем поведение

React Hook Form + useFormContext

При валидации, ошибках и сложной логике

Данные в одном form-контексте, меньше кода, меньше ререндеров

Пример: многошаговая форма с useState

import { useState } from 'react';

const initialData = {

 name: '',

 email: '',

 age: ''

};

function MultiStepForm() {

 const [step, setStep] = useState(0); // номер текущего шага

 const [formData, setFormData] = useState(initialData);

 const next = () => setStep((s) => s + 1); // перейти к следующему шагу

 const back = () => setStep((s) => s - 1); // вернуться назад

 return (

   <>

     {step === 0 && (

       <StepOne

         data={formData}

         onChange={(values) => setFormData({ ...formData, ...values })}

       />

     )}

     {step === 1 && (

       <StepTwo

         data={formData}

         onChange={(values) => setFormData({ ...formData, ...values })}

       />

     )}

     {/* Навигация */}

     <button onClick={back} disabled={step === 0}>Назад</button>

     <button onClick={next}>Далее</button>

   </>

 );

}

Пояснение:

  • formData хранит все сразу — удобно для сборки payload на сервер.

  • Компоненты StepOne, StepTwo — это переиспользуемые шаги.

  • Каждый шаг передает свои изменения через onChange.

Проверка dirty-состояния и защита от ухода

Если пользователь заполнил поля, но не отправил (dirty-состояние), например, случайно закрыв вкладку, мы можем предупредить его при попытке уйти со страницы.

Можно использовать window.onbeforeunload.

useEffect(() => {

   const isDirty = JSON.stringify(formData) !== JSON.stringify(initialData);

    const handleBeforeUnload = (e) => {

     if (isDirty) {

       e.preventDefault();

       e.returnValue = ''; // Стандартное поведение

     }

   };

    window.addEventListener('beforeunload', handleBeforeUnload);

   return () => window.removeEventListener('beforeunload', handleBeforeUnload);

 }, [formData]);

Можно также использовать предупреждение при переходе между страницами через react-router.

Пример: wizard-форма с RHF и useFormContext.

import { useForm, FormProvider, useFormContext } from 'react-hook-form';

function Step1() {

 const { register } = useFormContext();

 return <input {...register('email')} placeholder="Email" />;

}

function Step2() {

 const { register } = useFormContext();

 return <input {...register('age')} placeholder="Возраст" />;

}

export default function WizardForm() {

 const methods = useForm();

 const [step, setStep] = useState(0);

 return (

   <FormProvider {...methods}>

     <form onSubmit={methods.handleSubmit((data) => console.log(data))}>

       {step === 0 && <Step1 />}

       {step === 1 && <Step2 />}

       <button type="button" onClick={() => setStep((s) => s - 1)}>Назад</button>

       <button type="button" onClick={() => setStep((s) => s + 1)}>Далее</button>

       {step === 1 && <button type="submit">Отправить</button>}

     </form>

   </FormProvider>

 );

}

Пояснение:

  • Используем FormProvider, чтобы все шаги видели общую форму.

  • Каждый шаг получает register и другие функции из useFormContext.

  • Данные доступны сразу после submit без необходимости вручную собирать их между шагами.

Диаграмма состояний формы (wizard)

[Шаг 1] --→ [Шаг 2] --→ [Шаг 3] --→ [Отправка]

   ↑                              ↓

[Dirty? true] ← [Попытка закрыть вкладку/перейти]

Autosave и Optimistic Update в формах

Когда пользователь заполняет форму, важно:

  • не терять данные при случайном обновлении страницы или сбое соединения;

  • отправлять данные без лишней нагрузки (через debounce);

  • обновлять интерфейс мгновенно после действия пользователя (optimistic update).

Можно реализовать с помощью:

  • useEffect + debounce + localStorage — для автосохранения;

  • React Query или RTK Query — для мгновенного обновления UI при отправке.

Autosave: сохранение формы в localStorage с debounce

Мы сохраняем значения формы не при каждом изменении, а с задержкой (debounce), чтобы избежать спама в localStorage.

import { useForm } from 'react-hook-form';

import { useEffect, useRef } from 'react';

export function AutosaveForm() {

 const { register, watch } = useForm({

   defaultValues: JSON.parse(localStorage.getItem('draft') || '{}'),

 });

 const values = watch(); // следим за всеми полями

 const timeoutRef = useRef(null);

 useEffect(() => {

   if (timeoutRef.current) {

     clearTimeout(timeoutRef.current);

   }

   // откладываем сохранение

   timeoutRef.current = setTimeout(() => {

     localStorage.setItem('draft', JSON.stringify(values));

     console.log('✔ Автосохранено в localStorage');

   }, 1000); // 1 секунда тишины = сохраняем

 }, [values]);

 return (

   <form>

     <input {...register('name')} placeholder="Имя" />

     <input {...register('email')} placeholder="Email" />

   </form>

 );

}

Пояснение:

  • Используется watch — React Hook Form отслеживает любые изменения в полях.

  • setTimeout реализует поведение debounce.

  • localStorage — временное хранилище для черновиков, работает даже без интернета.

Когда использовать?

  • формы с несколькими шагами;

  • редактирование длинных текстов;

  • CMS, админки, формы настроек.

Optimistic Update: мгновенное обновление UI до ответа сервера

Иногда мы хотим сразу обновить интерфейс, не дожидаясь ответа от API. Например:

  • пользователь нажал «Сохранить» — и UI уже обновился;

  • в фоне идет запрос на сервер, а при ошибке мы откатываемся назад.

Пример с React Query и onMutate.

import { useMutation, useQueryClient } from '@tanstack/react-query';

import axios from 'axios';

function useUpdateUser() {

 const queryClient = useQueryClient();

 return useMutation({

   // Основная мутация

   mutationFn: (formData) => axios.post('/api/user', formData),

   // Оптимистичное обновление UI

   onMutate: async (newData) => {

     await queryClient.cancelQueries(['user']); // отменяем текущие запросы

     const previousData = queryClient.getQueryData(['user']); // сохраняем старое значение

     // Заменяем значение в кэше на новое

     queryClient.setQueryData(['user'], { ...previousData, ...newData });

     return { previousData }; // сохраняем для rollback

   },

   // Откат при ошибке

   onError: (err, newData, context) => {

     queryClient.setQueryData(['user'], context.previousData);

   },

   // Обновление после успеха

   onSuccess: () => {

     queryClient.invalidateQueries(['user']); // обновляем кэш с сервера

   }

 });

}

Пояснение:

  • onMutate вызывается до отправки запроса → сразу обновляет интерфейс.

  • onError откатывает данные, если что-то пошло не так.

  • onSuccess — переподгрузка данных с сервера, если нужно.

Когда использовать?

  • При обновлении профиля, заголовков, метаданных.

  • Если форма влияет на список, таблицу, карточки и нужно мгновенное обновление.

  • При редактировании элементов без полной перезагрузки страницы.

Интернационализация форм: yup/zod + react-i18next

Многоязычные формы — стандартная необходимость в интерфейсах, особенно если продукт работает в нескольких странах. Важно не только переводить подписи и плейсхолдеры, но и:

  • централизовать тексты ошибок;

  • не дублировать строки вручную в каждом компоненте;

  • поддерживать динамическое переключение языка без перезагрузки.

Что использовать?

Задача

Рекомендуемый подход

Перевод лейблов и плейсхолдеров

react-i18next и функция t()

Сообщения об ошибках в yup

t() внутри схем или глобально через setLocale()

Сообщения в zod

t() в .refine() или .min(msg) и т. п.

Пример 1: yup + react-i18next (ручной перевод)

Локализация сообщений ошибок через t():

import * as yup from 'yup';

import { useTranslation } from 'react-i18next';

export function useSchema() {

 const { t } = useTranslation();

 return yup.object({

   name: yup

     .string()

     .required(t('form.errors.required')),

   email: yup

     .string()

     .email(t('form.errors.email'))

     .required(t('form.errors.required')),

 });

}

Схему можно использовать внутри RHF через yupResolver.

Пример файла переводов (en.json)

{

 "form": {

   "placeholders": {

     "name": "Your name",

     "email": "Email address"

   },

   "errors": {

     "required": "This field is required",

     "email": "Invalid email format"

   }

 }

}

Пример 2: yup + глобальное переопределение setLocale

Если вы хотите избавиться от t() внутри схемы — можно переопределить все сообщения глобально.

import { setLocale } from 'yup';

import i18n from './i18n'; // ваш i18n-инстанс

setLocale({

 string: {

   email: () => i18n.t('form.errors.email'),

   min: ({ min }) => i18n.t('form.errors.min', { min }),

 },

 mixed: {

   required: () => i18n.t('form.errors.required'),

 },

});

После этого любой .required(), .min(), .email() будет выводить локализованное сообщение — без явных вызовов t() в схеме.

Пример 3: Zod + i18next

В zod используется .refine() для кастомных ошибок, и вы можете подставлять тексты через t() прямо в цепочке валидации.

import { z } from 'zod';

import { useTranslation } from 'react-i18next';

export function useZodSchema() {

 const { t } = useTranslation();

 return z.object({

   username: z

     .string()

     .min(3, t('form.errors.minUsername')),

   age: z

     .number()

     .min(18, t('form.errors.minAge')),

 });

}

Динамическая подгрузка языков (пример):

import i18n from 'i18next';

const changeLanguage = async (lang: string) => {

 await i18n.changeLanguage(lang); // переключение

 localStorage.setItem('lang', lang); // сохранить

};

Можно встроить в language switcher и обновлять на лету без перезагрузки. 

Пример использования плейсхолдеров через t():

<input

 {...register('email')}

 placeholder={t('form.placeholders.email')}

/>

Можно централизовать все плейсхолдеры в JSON и не дублировать их в коде. Централизованные плейсхолдеры позволяют использовать единую структуру переводов — удобно для UI-команд и дизайнеров.

Отладка и метрики в формах

Когда форма становится сложной (много шагов, валидация, API, автосохранение), важно иметь инструменты:

  1. Для отладки внутреннего состояния (React Hook Form DevTools).

  2. Для анализа поведения пользователей (например, где они чаще всего ошибаются или бросают заполнение).

1. Отладка с помощью React Hook Form DevTools

@hookform/devtools — это визуальный инструмент, который позволяет в реальном времени смотреть:

  • какие поля зарегистрированы;

  • какие из них "dirty" (изменены);

  • где есть ошибки;

  • текущее значение каждого поля.

Установка

npm install @hookform/devtools

Пример подключения

import { DevTool } from '@hookform/devtools';

import { useForm } from 'react-hook-form';

export default function MyForm() {

 const form = useForm();

 return (

   <form>

     <input {...form.register('email')} />

     <DevTool control={form.control} />

   </form>

 );

}

Как использовать?

  • В DevTools можно отслеживать:

    • изменения полей;

    • валидационные ошибки;

    • статус dirty / touched.

  • Особенно полезно:

    • при работе с useFormContext (многошаговые формы);

    • для выявления полей, которые случайно не зарегистрированы;

    • для дебага при автосохранении или ошибках от сервера.

2. Метрики: поведение пользователя в форме

Иногда нужно больше, чем просто техническая отладка, например:

  • в каких полях чаще всего происходят ошибки;

  • на каком шаге формы пользователи уходят;

  • сколько времени занимает заполнение формы.

Подход: логирование событий через аналитику

Можно отправлять события в Google Analytics, Яндекс Метрику, PostHog, Amplitude и так далее.

Пример: лог события ошибки

import ReactGA from 'react-ga4'; // или другой аналитический клиент

function logValidationError(field: string, message: string) {

 ReactGA.event({

   category: 'Form',

   action: 'Validation Error',

   label: field,

   value: message.length,

 });

}

Вызывается при возникновении ошибки.

if (errors.email) {

 logValidationError('email', errors.email.message);

}

Пример: лог времени заполнения

const start = performance.now();

// при отправке формы

const end = performance.now();

const duration = Math.round(end - start);

ReactGA.event({

 category: 'Form',

 action: 'Submit',

 label: 'registration',

 value: duration, // в миллисекундах

});
