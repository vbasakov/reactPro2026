# Тезисно — useRef

## Цель

Научиться использовать хук `useRef` в React для хранения значений между рендерами и доступа к DOM-элементам. Разобраться, как с помощью `ref.current` избежать лишних перерисовок компонента и безопасно управлять HTML-элементами напрямую.

## Почему важно

В React принято не взаимодействовать напрямую с DOM — это нарушает декларативный подход. Однако бывают ситуации, когда без прямого доступа не обойтись: фокус на инпут, измерение ширины элемента, сохранение предыдущего значения и так далее.

В этих случаях хук `useRef` — мощный инструмент. Он позволяет:

- сохранить данные между рендерами без триггера обновления;
- получить ссылку на DOM-элемент и работать с ним напрямую;
- заменить локальное состояние, если оно не влияет на отрисовку.

## Где используют useRef

### 1. Сохранение значения между рендерами

В React любое обновление состояния с помощью `useState` вызывает повторный рендер компонента. Но бывают ситуации, когда нужно сохранить информацию между рендерами, не вызывая при этом повторную отрисовку.

Например:

- Мы хотим отслеживать количество кликов, но не отображать это число в интерфейсе.
- Или сохранить время предыдущего действия без влияния на отображение.
- Или просто временно кешировать значение.

**Пример из UX:** На сайте доставки вы кликаете по кнопке «Отследить заказ», каждый клик сохраняется в `clickCount`. Пользователь не видит счетчик, но разработчики могут использовать его:

- для A/B-тестов (какой UI вызывает больше кликов);
- или чтобы после трех попыток показать уведомление: «Номер отслеживания скоро появится. Пожалуйста, подождите».

В таких случаях `useRef` — лучший выбор.

```tsx
import { useRef } from 'react';

function ClickTracker() {
  const clickCount = useRef(0);

  const handleClick = () => {
    clickCount.current += 1;
    // Нет ререндера, но значение сохраняется
    console.log('Total clicks:', clickCount.current);
  };

  return <button onClick={handleClick}>Отследить заказ</button>;
}
```

### 2. Доступ к DOM-элементам

Иногда вам нужно напрямую взаимодействовать с DOM-элементом — например, для фокусировки поля ввода.

```tsx
import { useRef } from 'react';

function FocusInput() {
  const inputRef = useRef<HTMLInputElement>(null);

  const handleFocus = () => {
    inputRef.current?.focus();
  };

  return (
    <>
      <input ref={inputRef} type="text" placeholder="Введите текст" />
      <button onClick={handleFocus}>Фокус</button>
    </>
  );
}
```

Важно: `ref` — это не состояние. Изменение `ref.current` не вызывает ререндер.

### 3. Хранение предыдущего значения

Часто нужно запомнить предыдущее значение пропса или состояния — например, для сравнения или анимаций.

```tsx
import { useRef, useEffect } from 'react';

function PreviousValue({ value }: { value: string }) {
  const prevValueRef = useRef(value);

  useEffect(() => {
    prevValueRef.current = value;
  }, [value]);

  return <div>Предыдущее: {prevValueRef.current}</div>;
}
```

### 4. Debounce с useRef

Для debounce-логики `useRef` идеален — таймер нужно хранить, но ререндер не нужен.

```tsx
import { useRef, useEffect } from 'react';

function DebouncedLogger({ value }: { value: string }) {
  const timerRef = useRef<ReturnType<typeof setTimeout> | null>(null);

  useEffect(() => {
    if (timerRef.current) clearTimeout(timerRef.current);
    timerRef.current = setTimeout(() => {
      console.log('Logged:', value);
    }, 1000);

    return () => {
      if (timerRef.current) clearTimeout(timerRef.current);
    };
  }, [value]);

  return <input value={value} onChange={(e) => {}} />;
}
```

## useRef vs useState: когда что выбирать

| Критерий | useRef | useState |
|----------|--------|----------|
| Вызывает ререндер | ❌ Нет | ✅ Да |
| Сохраняет между рендерами | ✅ Да | ✅ Да |
| Доступ к DOM | ✅ Да | ❌ Нет |
| Подходит для debounce | ✅ Да | ❌ Нет (бессмысленно) |
| Нужно для UI | ❌ Нет | ✅ Да |

## Итог

- `useRef` — для данных, которые НЕ влияют на UI.
- `useRef` — для доступа к DOM-элементам.
- `useRef` — для debounce, таймеров, счётчиков без ререндера.
- `useRef` — для хранения предыдущих значений без лишнего ререндера.
- Не используйте `useRef` для значений, которые нужно отображать в UI.
